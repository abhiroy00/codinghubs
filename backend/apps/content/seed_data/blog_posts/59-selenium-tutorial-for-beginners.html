Selenium WebDriver controls a real browser from code: it opens pages, clicks buttons, types into forms and reads what appears. It has been the standard tool for browser automation for many years and appears in a large number of QA job descriptions. This Selenium tutorial for beginners uses Python, because its syntax is short and easy to read; the same ideas apply in Java.

Step 1: Install Selenium

You need Python 3 and a browser such as Chrome. Create a virtual environment and install Selenium and pytest:

python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install selenium pytest

Recent Selenium 4 versions include Selenium Manager, which downloads the matching browser driver automatically, so you usually do not need to install ChromeDriver yourself.

Step 2: Open a browser

from selenium import webdriver

driver = webdriver.Chrome()
driver.get("https://example.com")
print(driver.title)
driver.quit()

Always call driver.quit() at the end, otherwise browser processes keep running in the background.

Step 3: Find elements with locators

Selenium finds elements using locators:

LocatorExampleUse when
IDBy.ID, "email"The element has a stable, unique id (best choice)
NameBy.NAME, "q"Form fields with a name attribute
CSS selectorBy.CSS_SELECTOR, "button[type='submit']"Flexible and fast; preferred over XPath for most cases
XPathBy.XPATH, "//button[text()='Login']"Matching by text or complex structure
Link textBy.LINK_TEXT, "Sign up"Links with fixed text

Avoid long, fragile XPaths copied from browser tools, such as /html/body/div[3]/div/form/button; they break whenever the layout changes. Ask developers to add stable attributes like data-testid.

Step 4: Interact with the page

from selenium.webdriver.common.by import By

driver.find_element(By.ID, "email").send_keys("student@example.com")
driver.find_element(By.ID, "password").send_keys("secret123")
driver.find_element(By.CSS_SELECTOR, "button[type='submit']").click()

Step 5: Wait correctly

Modern pages load content asynchronously. If your script looks for an element before it appears, the test fails. Never fix this with time.sleep(); use an explicit wait that waits only as long as needed:

from selenium.webdriver.support.ui import WebDriverWait
from selenium.webdriver.support import expected_conditions as EC

heading = WebDriverWait(driver, 10).until(
    EC.visibility_of_element_located((By.TAG_NAME, "h1"))
)

Step 6: Turn it into a real test with pytest

# test_example.py
import pytest
from selenium import webdriver
from selenium.webdriver.common.by import By


@pytest.fixture
def driver():
    d = webdriver.Chrome()
    yield d
    d.quit()


def test_home_page_heading(driver):
    driver.get("https://example.com")
    heading = driver.find_element(By.TAG_NAME, "h1").text
    assert heading == "Example Domain"

Run it with pytest -v. The fixture opens a fresh browser for each test and always closes it, even if the test fails.

Step 7: Run headless

On servers and CI pipelines there is no screen, so run Chrome in headless mode:

options = webdriver.ChromeOptions()
options.add_argument("--headless=new")
driver = webdriver.Chrome(options=options)

Common beginner mistakes

  • Using time.sleep() instead of explicit waits.
  • Fragile absolute XPaths.
  • Tests that depend on each other or on a fixed order.
  • No assertions, so the test "passes" without checking anything.
  • Repeating locators in every test instead of using the Page Object Model.

===FAQ=== Q: Is Selenium easy for beginners? A: Selenium is approachable once you know basic programming. The main skills to practise are choosing stable locators and using explicit waits correctly. Q: Should I learn Selenium with Java or Python? A: Both are widely used. Java is common in enterprise QA teams; Python is shorter and easier to start with. Check job listings for your target companies. Q: Do I still need to download ChromeDriver? A: Usually not. Recent Selenium 4 versions include Selenium Manager, which finds or downloads a matching driver automatically. Q: Why do my Selenium tests fail randomly? A: The most common causes are missing explicit waits, fragile locators and tests that depend on shared data or order. Fix those before adding retries.
