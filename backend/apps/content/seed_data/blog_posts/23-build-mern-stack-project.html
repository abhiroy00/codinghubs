Tutorials teach individual tools, but employers want to see that you can put them together. Building a complete MERN stack project is the best way to prove it. In this guide, we will plan and build a "Course Bookmarks" app where users sign up, log in, and save courses with notes. The same structure works for almost any MERN application.

Step 1: Plan before you code

Write down the features and data first:

  • Features: register, log in, log out; add, list, edit and delete bookmarks; each user sees only their own bookmarks.
  • Data: a User (name, email, password hash) and a Bookmark (title, url, notes, owner).
  • API endpoints: POST /api/auth/register, POST /api/auth/login, GET/POST /api/bookmarks, PUT/DELETE /api/bookmarks/:id.

Ten minutes of planning saves hours of rewriting.

Step 2: Project structure

course-bookmarks/
  server/
    src/
      models/        User.js, Bookmark.js
      routes/        auth.js, bookmarks.js
      middleware/    requireAuth.js
      index.js
    .env
  client/            (React app created with Vite)

Step 3: Set up the Express server

mkdir server && cd server
npm init -y
npm install express mongoose dotenv bcrypt jsonwebtoken cors

Add "type": "module" to package.json to use import syntax, then create src/index.js:

import 'dotenv/config';
import express from 'express';
import mongoose from 'mongoose';
import cors from 'cors';
import authRoutes from './routes/auth.js';
import bookmarkRoutes from './routes/bookmarks.js';

const app = express();
app.use(cors({ origin: process.env.CLIENT_URL }));
app.use(express.json());
app.use('/api/auth', authRoutes);
app.use('/api/bookmarks', bookmarkRoutes);

await mongoose.connect(process.env.MONGODB_URI);
app.listen(process.env.PORT || 5000, () => console.log('API ready'));

Your .env file holds MONGODB_URI, JWT_SECRET and CLIENT_URL. Add .env to .gitignore so secrets never reach GitHub.

Step 4: Define models with Mongoose

// models/Bookmark.js
import mongoose from 'mongoose';

const bookmarkSchema = new mongoose.Schema({
  title: { type: String, required: true, trim: true },
  url: { type: String, required: true },
  notes: String,
  owner: { type: mongoose.Schema.Types.ObjectId, ref: 'User', required: true },
}, { timestamps: true });

export default mongoose.model('Bookmark', bookmarkSchema);

The User model is similar, with a unique email and a passwordHash field.

Step 5: Authentication routes

// routes/auth.js (login handler)
router.post('/login', async (req, res) => {
  const { email, password } = req.body;
  const user = await User.findOne({ email });
  const valid = user && await bcrypt.compare(password, user.passwordHash);
  if (!valid) return res.status(401).json({ error: 'Invalid email or password' });
  const token = jwt.sign({ id: user._id }, process.env.JWT_SECRET, { expiresIn: '7d' });
  res.json({ token, name: user.name });
});

The register route hashes the password with bcrypt.hash(password, 12) before saving. Never store plain-text passwords.

Step 6: Protect routes with middleware

// middleware/requireAuth.js
export function requireAuth(req, res, next) {
  const token = req.headers.authorization?.split(' ')[1];
  try {
    req.userId = jwt.verify(token, process.env.JWT_SECRET).id;
    next();
  } catch {
    res.status(401).json({ error: 'Please log in' });
  }
}

In the bookmark routes, always filter by owner: Bookmark.find({ owner: req.userId }). This is what stops one user from seeing another user's data, and it is the most common security mistake in beginner projects.

Step 7: Test the API

Use Postman or a similar tool to register, log in, copy the token and call the bookmark endpoints with an Authorization: Bearer <token> header. Make sure invalid input returns helpful 400 errors and missing tokens return 401.

Step 8: Build the React front end

npm create vite@latest client -- --template react
cd client && npm install react-router-dom

Create pages for Register, Login and Bookmarks. Store the token after login, and send it with each request:

async function api(path, options = {}) {
  const token = localStorage.getItem('token');
  const res = await fetch(`${import.meta.env.VITE_API_URL}${path}`, {
    ...options,
    headers: { 'Content-Type': 'application/json', Authorization: `Bearer ${token}`, ...options.headers },
  });
  if (!res.ok) throw new Error((await res.json()).error || 'Request failed');
  return res.json();
}

Show loading and error states, disable the submit button while saving, and redirect to login when the API returns 401. (For production apps, HTTP-only cookies are often preferred over local storage for tokens; learn the trade-offs as you advance.)

Step 9: Polish the user experience

  • Responsive layout that works on phones.
  • Form validation with clear messages.
  • Confirmation before deleting.
  • Search or filter bookmarks.
  • Accessible labels on every input.

Step 10: Deploy

  1. Create a free cluster on a managed MongoDB service and copy the connection string.
  2. Deploy the Express server to a Node.js hosting platform and set environment variables there.
  3. Deploy the React app to a static host and set VITE_API_URL to your API address.
  4. Update CLIENT_URL on the server so CORS allows your live front end.

===FAQ=== Q: What is a good first MERN stack project? A: A to-do app, bookmark manager, blog or expense tracker with user login is a good first MERN project because it covers CRUD operations, authentication and deployment. Q: How long does it take to build a MERN project? A: A simple MERN project with authentication can take one to three weeks for a beginner, depending on features and experience. Q: Where can I deploy a MERN app for free? A: Many platforms offer free tiers for static front ends, Node.js back ends and managed MongoDB databases. Check each provider's current limits before choosing. Q: Should I use JWT or sessions in MERN apps? A: Both work. JWT is common in tutorials and APIs, while secure HTTP-only cookie sessions can be simpler to protect in browser-based apps. Understand the trade-offs before choosing.
