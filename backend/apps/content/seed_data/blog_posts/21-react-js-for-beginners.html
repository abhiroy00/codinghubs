React is a JavaScript library for building user interfaces, and it is one of the most requested front-end skills in job listings. It lets you build pages from small, reusable pieces called components, and it updates the screen efficiently when your data changes. This React JS for beginners guide explains the core ideas with simple examples you can run today.

What you should know first

React is JavaScript, so you should be comfortable with variables, functions, arrow functions, arrays and objects, array methods like map and filter, destructuring, modules (import/export) and promises. If these feel shaky, read JavaScript concepts to learn before React first.

Set up a React project

Install Node.js (LTS version), then create a project with Vite, a fast build tool:

npm create vite@latest my-app -- --template react
cd my-app
npm install
npm run dev

Open the address shown in the terminal. Edit src/App.jsx and the page updates instantly.

JSX: HTML-like syntax in JavaScript

JSX lets you write markup inside JavaScript:

function App() {
  const name = 'Coding Hubs';
  return <h1>Welcome to {name}</h1>;
}

A few rules: use className instead of class, close every tag (<img />), return a single parent element (or a fragment <>...</>), and put JavaScript expressions inside curly braces.

Components

A component is a function that returns JSX. Component names start with a capital letter.

function CourseCard() {
  return (
    <div className="card">
      <h2>Python Programming</h2>
      <p>Learn Python from scratch.</p>
    </div>
  );
}

export default function App() {
  return (
    <main>
      <CourseCard />
      <CourseCard />
    </main>
  );
}

Props: passing data to components

Props are inputs to a component, like function arguments:

function CourseCard({ title, weeks }) {
  return (
    <div className="card">
      <h2>{title}</h2>
      <p>{weeks} weeks</p>
    </div>
  );
}

<CourseCard title="React Full Stack" weeks={20} />

Props are read-only. A component should never change its own props.

State with useState

State is data that changes over time and causes the component to re-render:

import { useState } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <button onClick={() => setCount(count + 1)}>
      Clicked {count} times
    </button>
  );
}

Always update state with the setter function, never by changing the variable directly. When the new value depends on the old one, use the updater form: setCount((c) => c + 1).

Handling events

React events use camelCase names like onClick, onChange and onSubmit, and you pass a function, not a string. For forms, call event.preventDefault() to stop the page from reloading.

Rendering lists

const courses = [
  { id: 1, title: 'Python' },
  { id: 2, title: 'Java Full Stack' },
  { id: 3, title: 'MERN with Gen AI' },
];

function CourseList() {
  return (
    <ul>
      {courses.map((c) => <li key={c.id}>{c.title}</li>)}
    </ul>
  );
}

Each item needs a stable, unique key so React can track it efficiently. Avoid using the array index as a key when the list can change order.

Conditional rendering

{isLoggedIn ? <Dashboard /> : <LoginButton />}

Controlled forms

function SignupForm() {
  const [email, setEmail] = useState('');
  function handleSubmit(e) {
    e.preventDefault();
    console.log('Submitting', email);
  }
  return (
    <form onSubmit={handleSubmit}>
      <label htmlFor="email">Email</label>
      <input id="email" value={email} onChange={(e) => setEmail(e.target.value)} />
      <button type="submit">Sign up</button>
    </form>
  );
}

Side effects with useEffect

useEffect runs code after rendering, for example fetching data:

import { useEffect, useState } from 'react';

function Users() {
  const [users, setUsers] = useState([]);
  const [loading, setLoading] = useState(true);

  useEffect(() => {
    fetch('https://jsonplaceholder.typicode.com/users')
      .then((r) => r.json())
      .then((data) => setUsers(data))
      .finally(() => setLoading(false));
  }, []);   // empty array: run once after the first render

  if (loading) return <p>Loading…</p>;
  return <ul>{users.map((u) => <li key={u.id}>{u.name}</li>)}</ul>;
}

The dependency array controls when the effect runs again. Return a cleanup function to cancel timers or subscriptions.

Lifting state up

When two components need the same data, move the state to their closest common parent and pass it down as props. For data needed in many places (such as the logged-in user or theme), use Context or a state library later.

===FAQ=== Q: Is React easy for beginners? A: React is approachable if you already know JavaScript basics. Its core ideas, components, props and state, are few, but you need solid JavaScript to use them comfortably. Q: Is React a framework or a library? A: React is a library for building user interfaces. Frameworks such as Next.js build on React to add routing, server rendering and other features. Q: How long does it take to learn React? A: With good JavaScript knowledge, most learners understand React fundamentals in three to six weeks and become comfortable building projects in two to three months. Q: Should I learn JavaScript before React? A: Yes. Learning JavaScript fundamentals first makes React much easier, because most React problems are actually JavaScript problems.
