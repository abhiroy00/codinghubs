Many job descriptions for full stack developers now ask for experience integrating AI. Adding a smart feature to a web app is also one of the best ways to make your portfolio stand out. This guide shows you how to add AI to a web app properly: which features are worth building, how to structure the code, and how to keep it fast, affordable and safe.

Step 1: Choose a feature that solves a real problem

Good AI features save users time on a specific task. Examples:

  • Summarise: long reviews, documents, support tickets or meeting notes.
  • Generate drafts: product descriptions, email replies, job descriptions.
  • Extract: pull names, dates and amounts from invoices or resumes into form fields.
  • Classify: route support messages, tag content, detect sentiment.
  • Search in natural language: "show me weekend Python batches near Noida".
  • Answer questions from your app's help content with RAG.

Avoid adding a generic chatbot just because it is possible. A focused "Summarise" button that works well is more valuable than a chat box that does everything poorly.

Step 2: The right architecture

  1. The front end sends the user's request to your back end.
  2. The back end checks authentication, validates input and applies rate limits.
  3. The back end builds the prompt (instructions plus user data) and calls the LLM API with a secret key.
  4. The back end validates the model's output and returns it to the front end.

Never call the LLM API directly from browser code: your API key would be exposed, and you would lose control over cost and abuse.

Step 3: Design the prompt as code

// server/ai/summarise.js
const SYSTEM = `You summarise customer reviews for an online course store.
Write three bullet points: what customers like, what they dislike,
and one suggestion. Use only the reviews provided. Be neutral.`;

export function buildSummaryRequest(reviews) {
  const text = reviews.map((r, i) => `Review ${i + 1}: ${r.body}`).join('\n');
  return { system: SYSTEM, user: `<reviews>\n${text}\n</reviews>` };
}

Keep prompts in their own files, version them in Git, and change them deliberately like any other code.

Step 4: Use structured output

When your code needs to use the result, ask for JSON and validate it:

import { z } from 'zod';

const ResumeFields = z.object({
  name: z.string(),
  email: z.string().email().optional(),
  skills: z.array(z.string()).max(30),
  yearsOfExperience: z.number().min(0).max(50).optional(),
});

const parsed = ResumeFields.safeParse(JSON.parse(modelOutput));
if (!parsed.success) {
  // retry once, or show the user a manual form
}

Many LLM APIs offer a structured output or JSON mode that makes this more reliable. Always validate anyway.

Step 5: Stream long responses

LLM responses can take several seconds. Streaming sends text to the user as it is generated, which feels much faster. Most SDKs support streaming; forward the chunks to the browser using server-sent events or a streaming fetch response, and render them as they arrive.

Step 6: Control cost and speed

  • Use a smaller, faster model for simple tasks such as classification, and a more capable model only when needed.
  • Limit input length and maximum output tokens.
  • Cache results for identical requests, such as the summary of the same set of reviews.
  • Rate-limit per user and set a monthly budget in the provider dashboard.
  • Run non-urgent tasks (like tagging thousands of products) in background jobs.

Step 7: Design the user experience

  • Make it clear that content is AI-generated and may contain mistakes.
  • Let users edit AI drafts before saving or sending.
  • Show loading states and friendly error messages.
  • Provide a fallback when the AI service is unavailable, so the core app still works.
  • Ask for quick feedback (helpful / not helpful) to measure quality.

Step 8: Privacy and security

  • Send only the data the feature needs; remove personal details where possible.
  • Review the AI provider's data usage and retention terms.
  • Tell users how their data is used in your privacy policy.
  • Treat user-provided text as data in prompts, and protect against prompt injection.
  • Never let model output run as code or SQL without strict checks.
  • Escape AI-generated text before inserting it into HTML.

Step 9: Test AI features

AI output varies, so tests look a little different:

  • Unit-test your prompt builders and output validators like normal functions.
  • Mock the LLM API in automated tests so they are fast and free.
  • Keep an evaluation set of real inputs and expected properties, and run it when you change prompts or models.
  • Monitor production: error rates, latency, cost and user feedback.

===FAQ=== Q: Do I need to train my own model to add AI to my app? A: No. Most AI features use existing models through APIs. Your work is designing the feature, prompts, validation, user experience and safety. Q: Which AI features are easiest to add? A: Summarisation, text generation, classification and extraction are the easiest to start with because they need only a prompt and an API call. Q: How do I keep AI API costs low? A: Use smaller models for simple tasks, limit input and output length, cache repeated results, rate-limit users and set budget alerts. Q: Is it safe to send user data to an AI API? A: It can be, if you send only necessary data, review the provider's data policies, inform users in your privacy policy and follow applicable laws.
