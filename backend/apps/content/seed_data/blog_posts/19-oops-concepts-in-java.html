Object-oriented programming (OOP) is a way of organising code around "objects" that combine data and behaviour, much like things in the real world. Java is built around OOP, so understanding it well is essential for writing good Java code and for clearing interviews. This guide explains OOPs concepts in Java with everyday examples and simple code.

Class and object

A class is a blueprint. An object is a real thing built from that blueprint. Think of a car design (class) and the individual cars on the road (objects). Each car has its own colour and speed, but all follow the same design.

class Car {
    String colour;
    int speed;

    void accelerate(int amount) {
        speed += amount;
    }
}

Car myCar = new Car();
myCar.colour = "Red";
myCar.accelerate(40);

1. Encapsulation

Real-life example: an ATM. You can withdraw money through the machine's buttons, but you cannot reach in and change your balance directly. The bank controls access.

In Java, encapsulation means keeping fields private and exposing controlled methods:

class BankAccount {
    private double balance;

    public void deposit(double amount) {
        if (amount <= 0) throw new IllegalArgumentException("Invalid amount");
        balance += amount;
    }

    public boolean withdraw(double amount) {
        if (amount > balance) return false;
        balance -= amount;
        return true;
    }

    public double getBalance() {
        return balance;
    }
}

Benefit: data stays valid, because every change goes through rules you control.

2. Inheritance

Real-life example: every smartphone is a phone. It can make calls like any phone, and it adds extra features.

In Java, a child class inherits fields and methods from a parent class with extends:

class Employee {
    String name;
    double baseSalary;

    double salary() {
        return baseSalary;
    }
}

class Manager extends Employee {
    double bonus;

    @Override
    double salary() {
        return baseSalary + bonus;
    }
}

Java supports single inheritance for classes (a class extends only one class) but a class can implement many interfaces. Inheritance represents an "is-a" relationship: a Manager is an Employee.

3. Polymorphism

Real-life example: a person behaves differently in different roles: as a student in class, a customer in a shop, a player on the field. Same person, different behaviour depending on context.

Compile-time polymorphism (method overloading)

Same method name, different parameters:

class Calculator {
    int add(int a, int b) { return a + b; }
    double add(double a, double b) { return a + b; }
    int add(int a, int b, int c) { return a + b + c; }
}

Run-time polymorphism (method overriding)

A parent reference can point to a child object, and Java calls the child's version of the method at run time:

Employee e = new Manager();
System.out.println(e.salary());   // calls Manager's salary()

This is what makes code flexible: a payroll system can process a list of Employee objects without knowing which are managers, interns or contractors.

4. Abstraction

Real-life example: you drive a car using a steering wheel, pedals and gears without knowing how the engine works inside. The complex details are hidden.

Java achieves abstraction with abstract classes and interfaces:

interface PaymentMethod {
    void pay(double amount);
}

class UpiPayment implements PaymentMethod {
    public void pay(double amount) {
        System.out.println("Paid " + amount + " via UPI");
    }
}

class CardPayment implements PaymentMethod {
    public void pay(double amount) {
        System.out.println("Paid " + amount + " by card");
    }
}

PaymentMethod method = new UpiPayment();
method.pay(499);

The checkout code only knows about PaymentMethod. Adding a new payment type does not require changing it.

Other important OOP ideas

  • Composition ("has-a"): a Car has an Engine. Composition is often preferred over inheritance because it is more flexible.
  • Association, aggregation and composition: different strengths of relationships between objects.
  • Constructors and this/super: initialising objects and calling parent constructors.
  • The Object class: every class inherits toString(), equals() and hashCode().

Why OOP matters in real projects

OOP helps teams build large systems that are easier to understand, test and extend. Frameworks such as Spring Boot rely heavily on interfaces and polymorphism: you write against an interface, and Spring supplies the implementation. Good OOP design is the foundation of clean, maintainable code.

===FAQ=== Q: What are the four pillars of OOP in Java? A: Encapsulation, inheritance, polymorphism and abstraction. Q: Does Java support multiple inheritance? A: Java does not support multiple inheritance of classes, to avoid ambiguity, but a class can implement multiple interfaces. Q: What is the difference between overloading and overriding? A: Overloading means methods with the same name but different parameters in the same class, resolved at compile time. Overriding means a subclass provides its own version of a parent method, resolved at run time. Q: Is Java a pure object-oriented language? A: No. Java uses primitive types such as int and boolean, which are not objects, so it is not considered purely object-oriented.
