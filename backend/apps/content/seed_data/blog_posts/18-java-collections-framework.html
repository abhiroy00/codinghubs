Almost every Java program stores groups of objects: a list of students, a set of unique email addresses, a map from product IDs to prices. The Java Collections Framework provides ready-made, well-tested data structures for all of these. It is also one of the most frequently tested topics in Java interviews. This guide explains each part with examples and tells you when to use what.

The big picture

The framework is built around a few core interfaces:

  • Collection: the root interface for groups of elements.
  • List: ordered, allows duplicates, accessed by index.
  • Set: no duplicates.
  • Queue / Deque: elements processed in a specific order (FIFO, LIFO or priority).
  • Map: key–value pairs. Map is part of the framework but does not extend Collection.

A good habit is to declare variables using the interface and choose the implementation on the right: List<String> names = new ArrayList<>();. That way you can change the implementation later without changing the rest of the code.

List: ArrayList vs LinkedList

List<String> cities = new ArrayList<>();
cities.add("Delhi");
cities.add("Noida");
cities.add("Delhi");          // duplicates allowed
System.out.println(cities.get(1));   // Noida
ArrayListLinkedList

In practice, ArrayList is the right default for most programs.

Set: HashSet, LinkedHashSet and TreeSet

  • HashSet: fastest, no guaranteed order.
  • LinkedHashSet: keeps insertion order.
  • TreeSet: keeps elements sorted; operations are O(log n).
Set<String> emails = new HashSet<>();
emails.add("a@example.com");
emails.add("a@example.com");     // ignored, already present
System.out.println(emails.size()); // 1

Sets rely on equals() and hashCode() (or comparison for TreeSet) to detect duplicates, so your own classes must implement these correctly.

Map: HashMap, LinkedHashMap and TreeMap

Map<String, Integer> stock = new HashMap<>();
stock.put("laptop", 12);
stock.put("mouse", 40);
stock.merge("mouse", 5, Integer::sum);   // 45
System.out.println(stock.getOrDefault("keyboard", 0));   // 0

for (Map.Entry<String, Integer> e : stock.entrySet()) {
    System.out.println(e.getKey() + " = " + e.getValue());
}
  • HashMap: fast average O(1) lookups, no order, allows one null key.
  • LinkedHashMap: keeps insertion order (or access order, useful for LRU caches).
  • TreeMap: sorted by key, O(log n), useful for range queries.

How HashMap works internally

This is a favourite interview question. In short:

  1. When you call put(key, value), Java computes the key's hashCode() and uses it to choose a bucket in an internal array.
  2. If the bucket is empty, the entry is stored there.
  3. If other keys are already in that bucket (a collision), Java compares keys with equals(). If a matching key exists, its value is replaced; otherwise the new entry is added to the bucket.
  4. When a single bucket grows large, Java 8 and later convert it from a linked list into a balanced tree to keep lookups fast.
  5. When the map becomes too full (based on the load factor, 0.75 by default), the internal array is resized and entries are redistributed.

This is why keys should be immutable and must implement equals() and hashCode() consistently.

Queue and Deque

  • ArrayDeque: a fast double-ended queue, the recommended choice for stacks and queues.
  • PriorityQueue: always returns the smallest (or highest-priority) element first, useful in scheduling and algorithms like Dijkstra's.
Deque<Integer> stack = new ArrayDeque<>();
stack.push(1);
stack.push(2);
System.out.println(stack.pop());   // 2

Sorting collections

Use Comparable for a class's natural order and Comparator for custom orders:

record Student(String name, int marks) {}

List<Student> list = new ArrayList<>(List.of(
    new Student("Riya", 88), new Student("Kabir", 75), new Student("Meera", 92)));

list.sort(Comparator.comparingInt(Student::marks).reversed());

Iterating safely

Removing elements from a list inside a for-each loop throws ConcurrentModificationException. Use an Iterator with iterator.remove(), or list.removeIf(...).

Thread-safe collections

Standard collections are not thread-safe. For concurrent code, use classes from java.util.concurrent such as ConcurrentHashMap and CopyOnWriteArrayList.

===FAQ=== Q: What is the difference between List and Set in Java? A: A List keeps elements in order and allows duplicates, while a Set does not allow duplicate elements and may or may not keep order depending on the implementation. Q: What is the difference between HashMap and Hashtable? A: HashMap is not synchronised and allows one null key and null values. Hashtable is a legacy synchronised class that does not allow null keys or values. For thread safety, ConcurrentHashMap is preferred today. Q: Why should I override equals() and hashCode() together? A: Hash-based collections use hashCode() to find a bucket and equals() to compare keys. If they are inconsistent, lookups and duplicate detection will not work correctly. Q: Which Java collection is fastest? A: It depends on the operation. ArrayList is fastest for index access, while HashMap and HashSet offer average constant-time lookups.
