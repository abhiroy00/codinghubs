A project that only runs on your laptop is hard for anyone else to see. A live link on your resume lets recruiters try your work in seconds, and the process of deploying teaches you skills that every company uses. This guide explains how to deploy a full stack project step by step, from choosing hosting to fixing the most common errors.

The three parts you are deploying

  1. Front end: your React, Angular or Vue app. After building, it is just static files: HTML, CSS, JavaScript and images.
  2. Back end: your Node.js, Django, FastAPI or Spring Boot server, which must run continuously.
  3. Database: PostgreSQL, MySQL or MongoDB, which must be reachable from the back end and protected from everyone else.

You can host all three in one place, or use a separate specialised service for each.

For a first deployment, a front-end platform plus a PaaS and a managed database is the easiest path. Check each provider's current free-tier limits, as they change over time.

Step 1: Prepare your code

  • Push your project to GitHub. Most platforms deploy directly from a repository.
  • Move every secret (database URLs, API keys, JWT secrets) into environment variables. Never commit .env files.
  • Make the server port configurable: const PORT = process.env.PORT || 5000;
  • Make the API URL configurable in the front end, for example import.meta.env.VITE_API_URL in a Vite app.
  • Add a start script to your back end (for example "start": "node src/index.js").

Step 2: Deploy the database

Create a database on a managed service, then:

  1. Create a database user with a strong password.
  2. Restrict network access to your back end where possible.
  3. Copy the connection string into your back end's environment variables.
  4. Run migrations (for SQL databases) to create tables.

Step 3: Deploy the back end

  1. Create a new web service on your hosting platform and connect your GitHub repository.
  2. Set the build command (for example npm install) and start command (for example npm start).
  3. Add environment variables: database URL, secrets and the allowed front-end origin for CORS.
  4. Deploy, then open a health endpoint such as /api/health to confirm it works.

For Django, use a production server such as Gunicorn, set DEBUG=False, configure ALLOWED_HOSTS and collect static files. For Spring Boot, build a JAR with Maven or Gradle and run it with java -jar.

Step 4: Deploy the front end

  1. Create a new project on a front-end hosting platform and connect the repository.
  2. Set the build command (often npm run build) and output folder (dist for Vite, build for Create React App).
  3. Set VITE_API_URL (or equivalent) to your live back-end URL.
  4. For single-page apps with client-side routing, configure a rewrite so every path serves index.html; otherwise refreshing a page like /dashboard returns 404.

Step 5: Connect a custom domain and HTTPS

Buy a domain from a registrar, then add the DNS records your hosting provider gives you (usually an A record or CNAME). Most platforms issue free HTTPS certificates automatically. A custom domain such as yourname.dev looks professional on a resume.

Deploying with Docker (next level)

Docker packages your app with everything it needs, so it runs the same on your laptop and on the server:

FROM node:20-alpine
WORKDIR /app
COPY package*.json ./
RUN npm ci --omit=dev
COPY . .
EXPOSE 5000
CMD ["node", "src/index.js"]

With Docker Compose, you can run the front end, back end and database together locally and deploy the same setup to a VPS.

Common deployment errors and fixes

CORS error in the browserBack end does not allow the front-end originSet the CORS origin to your live front-end URL
API calls go to localhostHard-coded URL in the front endUse an environment variable and rebuild
404 when refreshing a pageNo SPA rewrite ruleRewrite all routes to index.html

Mixed content warningHTTPS front end calling an HTTP APIServe the API over HTTPS

After deployment

  • Test the full flow on mobile and desktop.
  • Check logs regularly and set up basic uptime monitoring.
  • Back up your database.
  • Automate deployment with a CI/CD pipeline such as GitHub Actions so every push to the main branch deploys after tests pass.

===FAQ=== Q: Can I deploy a full stack project for free? A: Yes. Many platforms offer free tiers for front ends, back ends and databases. Free tiers often have limits, such as servers sleeping when idle, so check current terms. Q: What is the easiest way to deploy a React app? A: Connect your GitHub repository to a front-end hosting platform, set the build command and output folder, and add any environment variables. The platform builds and deploys automatically. Q: Why does my deployed app show a CORS error? A: The back end is not allowing requests from your front-end domain. Add your live front-end URL to the back end's CORS configuration. Q: Do I need Docker to deploy my project? A: No. Many platforms deploy directly from your code. Docker is useful for consistency and for deploying to your own servers, and it is a valuable skill to learn later.
