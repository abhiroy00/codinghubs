Node.js lets you run JavaScript on a server, and Express is the most popular framework for building web servers and APIs with it. Together they are the "E" and "N" in the MERN stack. In this tutorial you will build a Node.js REST API for managing tasks and learn the patterns used in real back-end projects.

What is a REST API?

A REST API lets clients (a React app, a mobile app or another server) work with data over HTTP using standard methods:

MethodEndpointAction
GET/api/tasksList tasks
GET/api/tasks/:idGet one task
POST/api/tasksCreate a task
PATCH/api/tasks/:idUpdate part of a task
DELETE/api/tasks/:idDelete a task

Responses use JSON and meaningful status codes: 200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 404 Not Found and 500 Internal Server Error.

Step 1: Set up the project

mkdir tasks-api && cd tasks-api
npm init -y
npm install express
npm install --save-dev nodemon

In package.json, add "type": "module" and a script "dev": "nodemon src/index.js". Nodemon restarts the server when you save a file.

Step 2: Your first server

// src/index.js
import express from 'express';

const app = express();
app.use(express.json());   // parse JSON request bodies

app.get('/api/health', (req, res) => {
  res.json({ status: 'ok' });
});

const PORT = process.env.PORT || 5000;
app.listen(PORT, () => console.log(`Server running on port ${PORT}`));

Run npm run dev and open http://localhost:5000/api/health.

Step 3: CRUD routes

Start with an in-memory array to focus on Express itself:

let tasks = [];
let nextId = 1;

app.get('/api/tasks', (req, res) => {
  const { done } = req.query;   // e.g. /api/tasks?done=true
  const result = done === undefined ? tasks : tasks.filter((t) => String(t.done) === done);
  res.json(result);
});

app.post('/api/tasks', (req, res) => {
  const { title } = req.body;
  if (!title || !title.trim()) {
    return res.status(400).json({ error: 'Title is required' });
  }
  const task = { id: nextId++, title: title.trim(), done: false };
  tasks.push(task);
  res.status(201).json(task);
});

app.patch('/api/tasks/:id', (req, res) => {
  const task = tasks.find((t) => t.id === Number(req.params.id));
  if (!task) return res.status(404).json({ error: 'Task not found' });
  if (typeof req.body.done === 'boolean') task.done = req.body.done;
  if (req.body.title) task.title = req.body.title.trim();
  res.json(task);
});

app.delete('/api/tasks/:id', (req, res) => {
  const before = tasks.length;
  tasks = tasks.filter((t) => t.id !== Number(req.params.id));
  if (tasks.length === before) return res.status(404).json({ error: 'Task not found' });
  res.status(204).end();
});

Test every route with Postman or a similar tool. Notice the difference between route parameters (req.params), query strings (req.query) and the body (req.body).

Step 4: Understand middleware

Middleware functions run between the request arriving and the response being sent. They can read or change the request, end the response, or call next() to continue.

function logger(req, res, next) {
  const start = Date.now();
  res.on('finish', () => {
    console.log(`${req.method} ${req.originalUrl} ${res.statusCode} ${Date.now() - start}ms`);
  });
  next();
}
app.use(logger);

Authentication, logging, CORS, rate limiting and body parsing are all middleware.

Step 5: Central error handling

// after all routes
app.use((req, res) => res.status(404).json({ error: 'Route not found' }));

app.use((err, req, res, next) => {
  console.error(err);
  res.status(err.status || 500).json({ error: err.status ? err.message : 'Something went wrong' });
});

In Express 5, errors thrown inside async route handlers are passed to this handler automatically. In Express 4, wrap async handlers or call next(err) yourself. Never send internal error details to clients in production.

Step 6: Organise the project

src/
  index.js            app setup
  routes/tasks.js     express.Router() with the task routes
  controllers/        request handling functions
  services/           business logic
  models/             database models
  middleware/         auth, validation, errors

Use express.Router() to group related routes and mount them with app.use('/api/tasks', taskRouter).

Step 7: Connect a database

Replace the in-memory array with a real database. With MongoDB, use Mongoose models; with PostgreSQL or MySQL, use a query builder or ORM such as Prisma, Drizzle, Sequelize or Knex. Keep the connection string in an environment variable loaded from a .env file that is never committed.

Step 8: Validate input

Never trust client data. Libraries such as Zod, Joi or express-validator check types, required fields and formats before data reaches your database, and return clear 400 errors.

Step 9: Security basics

  • Hash passwords with bcrypt and use JWT or secure sessions for login.
  • Configure CORS to allow only your front-end domain.
  • Add security headers with Helmet and rate limiting on login routes.
  • Filter every query by the logged-in user where data is private.
  • Keep dependencies updated and run npm audit.

Step 10: Test and deploy

Write API tests with a test runner and Supertest, then deploy to a Node.js hosting platform or a cloud server. Set environment variables in the hosting dashboard, and check logs after deployment.

===FAQ=== Q: Is Node.js good for building APIs? A: Yes. Node.js handles many simultaneous connections efficiently, and Express makes building REST APIs simple, which is why they are widely used for web and mobile back ends. Q: What is middleware in Express? A: Middleware is a function that runs during the request-response cycle. It can modify the request or response, end the request, or pass control to the next function with next(). Q: Should I use Express or another Node.js framework? A: Express is the most common choice and great for learning. Alternatives such as Fastify and NestJS are popular for performance or more structured, larger projects. Q: Which database is best with Node.js? A: MongoDB is common in MERN projects, while PostgreSQL and MySQL are popular for relational data. Choose based on your data and the job roles you are targeting.
