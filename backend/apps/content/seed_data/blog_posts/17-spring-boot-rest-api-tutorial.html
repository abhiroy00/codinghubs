Spring Boot is the most popular framework for building back-end applications in Java. It removes most of the configuration that older Spring projects needed, so you can build a production-style REST API quickly. In this Spring Boot tutorial, you will build a simple course catalogue API step by step and learn the structure used in real projects.

What you need

  • A recent JDK (version 17 or later is a good choice).
  • An IDE such as IntelliJ IDEA Community Edition, Eclipse or VS Code with Java extensions.
  • Basic Core Java and OOP knowledge.
  • Postman or a similar tool to test APIs.

Step 1: Create the project

Go to Spring Initializr (start.spring.io) and choose:

  • Project: Maven, Language: Java.
  • Dependencies: Spring Web, Spring Data JPA, Validation and H2 Database (an in-memory database, good for learning).

Download the project, unzip it and open it in your IDE. The main class has the @SpringBootApplication annotation, which enables auto-configuration and component scanning. Run it, and an embedded web server starts on port 8080.

Step 2: Understand the layered structure

LayerResponsibilityAnnotation
ControllerHandles HTTP requests and responses@RestController
ServiceBusiness logic@Service
RepositoryDatabase access@Repository (or a Spring Data interface)
EntityMaps a Java class to a database table@Entity

Keeping these layers separate makes code easier to test and change.

Step 3: Create an entity

@Entity
public class Course {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @NotBlank
    private String title;

    @Min(1)
    private int durationWeeks;

    // getters and setters
}

JPA (through Hibernate) creates a course table from this class. The validation annotations come from the Validation starter.

Step 4: Create a repository

public interface CourseRepository extends JpaRepository<Course, Long> {
    List<Course> findByTitleContainingIgnoreCase(String keyword);
}

Spring Data JPA generates the implementation for you, including save, findById, findAll and deleteById. It even creates queries from method names like findByTitleContainingIgnoreCase.

Step 5: Add a service

@Service
public class CourseService {
    private final CourseRepository repository;

    public CourseService(CourseRepository repository) {
        this.repository = repository;
    }

    public List<Course> findAll() {
        return repository.findAll();
    }

    public Course findById(Long id) {
        return repository.findById(id)
                .orElseThrow(() -> new CourseNotFoundException(id));
    }

    public Course create(Course course) {
        return repository.save(course);
    }
}

Notice constructor injection: Spring creates the repository and passes it in. This is called dependency injection and is a core Spring idea.

Step 6: Build the REST controller

@RestController
@RequestMapping("/api/courses")
public class CourseController {
    private final CourseService service;

    public CourseController(CourseService service) {
        this.service = service;
    }

    @GetMapping
    public List<Course> all() {
        return service.findAll();
    }

    @GetMapping("/{id}")
    public Course one(@PathVariable Long id) {
        return service.findById(id);
    }

    @PostMapping
    @ResponseStatus(HttpStatus.CREATED)
    public Course create(@Valid @RequestBody Course course) {
        return service.create(course);
    }
}

Run the application and test it in Postman: send POST /api/courses with a JSON body such as {"title": "Java Full Stack", "durationWeeks": 24}, then GET /api/courses.

Step 7: Handle errors properly

Create a custom exception and a global handler so clients receive clear error responses:

@RestControllerAdvice
public class ApiErrors {
    @ExceptionHandler(CourseNotFoundException.class)
    @ResponseStatus(HttpStatus.NOT_FOUND)
    public Map<String, String> notFound(CourseNotFoundException e) {
        return Map.of("error", e.getMessage());
    }
}

Invalid input (for example an empty title) automatically returns a 400 Bad Request because of @Valid. You can add another handler to format those messages nicely.

Step 8: Configure the application

Settings live in application.properties or application.yml. For example, change the port or enable the H2 console:

server.port=8081
spring.h2.console.enabled=true

When you move to MySQL or PostgreSQL, you add the database driver and set the connection URL, username and password, ideally from environment variables.

Step 9: Write a test

Spring Boot includes JUnit and Mockito. Test the service layer with mocks, and use @WebMvcTest with MockMvc to test controllers without starting a full server. Tests give you confidence to change code later.

===FAQ=== Q: What is Spring Boot used for? A: Spring Boot is used to build Java back-end applications such as REST APIs, web applications and microservices quickly, with sensible defaults and minimal configuration. Q: Is Spring Boot hard for beginners? A: It is approachable if you already understand Core Java, OOP and basic SQL. Most difficulties come from weak fundamentals rather than Spring Boot itself. Q: What is the difference between Spring and Spring Boot? A: Spring is the broader framework. Spring Boot builds on it with auto-configuration, starter dependencies and an embedded server, so you can create applications with far less setup. Q: Which database should I use with Spring Boot? A: H2 is convenient for learning. MySQL and PostgreSQL are common choices for real projects.
