How should you practise a React interview answer?

Start with the user-visible behavior, explain the relevant React concept, and walk through a small example and a failure case. For an asynchronous search component, explain which state is local, how stale requests are ignored and what the loading and error states show. State updates and network responses do not necessarily finish in the order they started.

For keys, describe what happens when a list is reordered. For effects, identify the external system being synchronized and how cleanup works. Use the existing questions below as a checklist, then build one working example. Revise JavaScript fundamentals and compare the React Full Stack course topics rather than memorizing definitions alone.

React is the most requested front-end skill in many job listings, so React questions appear in front-end, full stack and MERN interviews. Interviewers want to know whether you understand how React works, not just its syntax. These 35 React interview questions cover fundamentals for freshers and deeper topics often asked of experienced candidates.

Fundamentals

1. What is React?

React is an open-source JavaScript library for building user interfaces from reusable components. It updates the UI efficiently when data changes.

2. What is JSX?

JSX is a syntax extension that lets you write HTML-like markup in JavaScript. Build tools compile it into regular JavaScript function calls that create React elements.

3. What is the virtual DOM?

A lightweight in-memory representation of the UI. When state changes, React creates a new tree, compares it with the previous one (reconciliation) and applies only the necessary changes to the real DOM.

4. What is the difference between a component and an element?

A component is a function (or class) that returns UI. An element is the plain object describing what to render, produced when you write JSX like <Button />.

5. What is the difference between props and state?

Props are inputs passed from a parent and are read-only inside the component. State is data owned and managed by the component that can change over time and triggers re-renders.

6. What are controlled and uncontrolled components?

In a controlled component, form input values are stored in React state and updated via onChange. In an uncontrolled component, the DOM holds the value, which you read with a ref.

7. Why are keys important in lists?

Keys help React identify which items changed, were added or removed. They should be stable and unique, such as database IDs. Using array indexes as keys can cause bugs when items are reordered.

8. What is a fragment?

A wrapper (<>...</> or <React.Fragment>) that groups elements without adding an extra DOM node.

9. What is conditional rendering?

Showing different UI based on conditions, using if statements, the ternary operator or &&.

10. What is lifting state up?

Moving shared state to the closest common parent so that sibling components can access and update it through props.

Hooks

11. What are hooks?

Functions such as useState and useEffect that let function components use state, side effects and other React features.

12. What are the rules of hooks?

Call hooks only at the top level of a component or custom hook (not in loops, conditions or nested functions), and only from React function components or custom hooks.

13. How does useState work?

It returns the current state value and a setter function. Calling the setter schedules a re-render with the new value. Use the updater form setCount(c => c + 1) when the new state depends on the previous state.

14. What is useEffect used for?

Synchronising a component with external systems: fetching data, subscriptions, timers or manually changing the DOM. It runs after render.

15. Explain the useEffect dependency array.

No array: runs after every render. Empty array: runs after the first render (and again in development when Strict Mode intentionally re-runs effects). With dependencies: runs when any listed value changes. Return a cleanup function to undo the effect.

useEffect(() => {
  const id = setInterval(() => setSeconds((s) => s + 1), 1000);
  return () => clearInterval(id);   // cleanup
}, []);

16. What is useRef?

It returns a mutable object whose .current value persists across renders without causing re-renders. Used for DOM references and storing values like timer IDs.

17. What is the difference between useMemo and useCallback?

useMemo memoises a computed value; useCallback memoises a function. Both recompute only when dependencies change and are useful for performance optimisation.

18. What is useContext?

A hook that reads a value from React Context, avoiding passing props through many layers (prop drilling).

19. What is useReducer?

An alternative to useState for complex state logic, using a reducer function (state, action) => newState.

20. What is a custom hook?

A function starting with use that combines other hooks to reuse stateful logic, such as useFetch or useLocalStorage.

Rendering and performance

21. When does a React component re-render?

When its state changes, when its parent re-renders, or when a context it uses changes.

22. What is React.memo?

A higher-order component that skips re-rendering a component when its props have not changed (shallow comparison).

23. How do you optimise React performance?

Avoid unnecessary state, keep state close to where it is used, memoise expensive calculations and components where profiling shows a benefit, virtualise long lists, lazy-load routes and components, and reduce bundle size.

24. What is code splitting?

Splitting the JavaScript bundle so parts load only when needed, using React.lazy and Suspense or route-based splitting.

25. What is Strict Mode?

A development-only tool that highlights potential problems, for example by intentionally running some functions and effects twice to reveal side effects that are not cleaned up correctly.

26. Why should you not mutate state directly?

React detects changes by comparing references. Mutating an object or array in place may not trigger a re-render and leads to bugs. Always create new objects and arrays.

Architecture and ecosystem

27. What is prop drilling and how do you avoid it?

Passing props through many intermediate components that do not need them. Avoid it with Context, composition (passing components as children) or a state management library.

28. When would you use Redux or another state library?

When many unrelated components share complex, frequently updated state. Redux Toolkit, Zustand and similar libraries provide predictable updates and good developer tools. For server data, tools like TanStack Query handle caching and refetching.

29. How does routing work in React apps?

Libraries like React Router map URLs to components on the client side, so navigation does not reload the page. Frameworks like Next.js provide file-based routing.

30. What is the difference between client-side rendering and server-side rendering?

With client-side rendering, the browser downloads JavaScript and builds the page. With server-side rendering, the server sends ready HTML, improving first load and SEO, and React then hydrates it to add interactivity.

31. What are React Server Components?

Components that run only on the server (supported by frameworks such as Next.js), fetch data close to the source and send rendered output to the client, reducing the JavaScript shipped to the browser.

32. What are error boundaries?

Components that catch rendering errors in their child tree and display a fallback UI instead of crashing the whole app.

Testing and practical questions

33. How do you test React components?

With a test runner such as Jest or Vitest and React Testing Library, testing behaviour from the user's perspective: rendering, clicking, typing and checking what appears on screen.

34. How do you fetch data in React?

In useEffect with fetch or a client library, handling loading and error states and cancelling stale requests, or with a data-fetching library such as TanStack Query, or through server components and loaders in a framework.

35. Build a counter that cannot go below zero.

function Counter() {
  const [count, setCount] = useState(0);
  return (
    <div>
      <button onClick={() => setCount((c) => Math.max(0, c - 1))}>-</button>
      <span>{count}</span>
      <button onClick={() => setCount((c) => c + 1)}>+</button>
    </div>
  );
}

How to prepare

  • Revise JavaScript fundamentals: closures, promises, the event loop and array methods are asked alongside React.
  • Build small components live: a to-do list, a search filter, a modal, a fetch-and-display list.
  • Be able to explain why your code re-renders and how you would optimise it.
  • Prepare to walk through a React project you built.

===FAQ=== Q: What React topics are asked most in interviews? A: Props vs state, hooks (especially useState and useEffect), keys, the virtual DOM, re-rendering, performance optimisation, context and state management. Q: Do React interviews include JavaScript questions? A: Yes. Most React interviews include JavaScript fundamentals such as closures, promises, async/await, the event loop, this, and array methods. Q: Are class components still asked about in interviews? A: Occasionally, for maintaining older code. Most modern interviews focus on function components and hooks. Q: How can I practise React for interviews? A: Build small components from scratch without tutorials, time yourself, and explain your decisions aloud as you would in a live coding round.
