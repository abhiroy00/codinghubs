Building a chatbot is one of the best first projects in generative AI. It teaches you how large language model APIs work, how conversations are managed, and how to turn an AI model into a useful product. In this guide you will build an AI chatbot for a coding institute's FAQ, step by step, with Python. The same approach works for customer support, study helpers and internal tools.

How an LLM chatbot works

  1. The user types a message in a chat interface.
  2. Your back end sends the conversation (instructions plus previous messages plus the new message) to an LLM API.
  3. The model returns a reply.
  4. Your back end sends the reply to the interface and stores it in the conversation history.

The model itself does not remember previous turns between API calls. Your application provides the memory by sending the relevant history each time.

Step 1: Choose an LLM API

Several companies provide LLM APIs with official Python and JavaScript SDKs. Compare them on answer quality for your use case, speed, cost per token, context window size, data and privacy policies, and the languages your users speak. Most offer a free or low-cost way to experiment. Read the provider's current documentation for exact model names and SDK syntax, as these change regularly.

Step 2: Keep your API key secret

  • Store the key in an environment variable or a .env file that is listed in .gitignore.
  • Never put the key in front-end JavaScript; anyone can read code that runs in the browser.
  • Call the API only from your back end.
  • Set usage limits or budgets in the provider dashboard.

Step 3: Write a system prompt

The system prompt defines the chatbot's job, tone and limits:

You are the help assistant for a coding institute.
Answer questions about courses, schedules and admissions using only the
information provided below. Be friendly, concise and use simple English.
If a question is not covered, say you are not sure and suggest contacting
the admissions team. Never invent fees, dates or placement numbers.

Information:
...course details, timings and policies...

Clear limits ("never invent fees") are what make a chatbot trustworthy.

Step 4: Send a conversation to the API

The exact function names depend on your provider's SDK, but the structure is similar everywhere:

import os
from dotenv import load_dotenv

load_dotenv()
SYSTEM_PROMPT = open("system_prompt.txt", encoding="utf-8").read()

def ask_model(history, user_message, client):
    messages = history + [{"role": "user", "content": user_message}]
    # Replace with your provider's chat/messages call:
    reply = client.chat(system=SYSTEM_PROMPT, messages=messages, max_tokens=500)
    history.append({"role": "user", "content": user_message})
    history.append({"role": "assistant", "content": reply})
    return reply

Step 5: Manage conversation history

Every token you send costs money and uses the context window. Common strategies:

  • Keep only the last few exchanges.
  • Summarise older parts of the conversation into a short note.
  • Store history per user session in a database or cache, keyed by a session ID.

Step 6: Build a simple API with FastAPI

from fastapi import FastAPI
from pydantic import BaseModel

app = FastAPI()
sessions = {}   # use a database or cache in production

class ChatIn(BaseModel):
    session_id: str
    message: str

@app.post("/api/chat")
def chat(body: ChatIn):
    history = sessions.setdefault(body.session_id, [])
    reply = ask_model(history[-10:], body.message, client)
    return {"reply": reply}

Step 7: Add a chat interface

Create a simple web page or React component with a message list, an input box and a send button. Show a "typing…" indicator while waiting, disable the button during the request, and display friendly errors. For a better experience, use your provider's streaming option so the reply appears word by word.

Step 8: Add guardrails

  • Input limits: cap message length and requests per user to control cost and abuse.
  • Topic limits: tell the model to stay on its subject and politely decline unrelated requests.
  • Prompt injection: users may type "ignore your instructions". Keep sensitive data out of prompts, and never let the model perform actions without checks in your code.
  • Human handoff: offer a way to contact a real person.
  • Logging: record conversations (with user consent and privacy in mind) to find mistakes.

Step 9: Test with real questions

Write 20–30 questions real users would ask, including tricky ones: questions with no answer in your information, ambiguous questions, and attempts to make the bot go off-topic. Check every answer. Update the system prompt and information, and test again. This simple evaluation loop is what separates demo chatbots from reliable ones.

Step 10: Deploy

Deploy the FastAPI back end to a cloud platform with your API key set as an environment variable, deploy the front end to a static host, and restrict CORS to your domain. Monitor usage and costs in the provider dashboard.

Ideas to extend your chatbot

  • Answer from long documents using retrieval-augmented generation (RAG).
  • Let the bot call tools, such as checking batch timings from a database, which turns it into an AI agent.
  • Support Hindi and other Indian languages.
  • Add voice input and output.

===FAQ=== Q: Can I build an AI chatbot without machine learning knowledge? A: Yes. With an LLM API, you mainly need programming skills, usually Python or JavaScript, plus good prompt design. You do not need to train a model yourself. Q: How much does it cost to run an AI chatbot? A: Costs depend on the provider, the model, the number of users and how much text is sent per conversation. Limiting history length and message size helps control costs. Q: Why does my chatbot give wrong answers? A: LLMs can hallucinate when they lack information. Provide accurate source information, instruct the bot to say when it does not know, and test with real questions. Q: Should I call the LLM API from the front end? A: No. Call it from your back end so your API key stays secret and you can add limits, logging and validation.
