Automation testing interviews usually combine testing fundamentals, Selenium concepts, programming basics and questions about the framework you built. These 35 Selenium interview questions cover what freshers and experienced testers are asked most often, with short answers you can explain in your own words.

Testing fundamentals

1. What is automation testing?

Using scripts and tools to execute tests and compare actual results with expected results, instead of testing manually. See what is automation testing.

2. Which tests should be automated?

Repeated, stable, important and deterministic tests: regression, smoke, data-driven and API tests. Exploratory and usability testing stay manual.

3. What is regression testing?

Re-running tests after changes to confirm that existing features still work.

4. What is the difference between smoke and sanity testing?

Smoke testing checks that a build is stable enough for further testing by covering critical paths broadly. Sanity testing is a narrow check that a specific fix or change works.

5. What is the test pyramid?

A guideline to have many fast unit tests, fewer API/integration tests and a small number of slower UI end-to-end tests.

Selenium basics

6. What is Selenium WebDriver?

A tool and W3C standard API that controls real browsers from code to automate web application testing.

7. What are the components of the Selenium suite?

Selenium WebDriver (browser automation), Selenium IDE (record and playback browser extension) and Selenium Grid (running tests on multiple machines and browsers in parallel).

8. Which locators does Selenium support?

ID, name, class name, tag name, link text, partial link text, CSS selector and XPath.

9. Which locator should you prefer?

A stable unique ID or a dedicated test attribute such as data-testid, then concise CSS selectors. Avoid long absolute XPaths.

10. What is the difference between absolute and relative XPath?

Absolute XPath starts from the root (/html/body/...) and breaks easily. Relative XPath starts with // and targets elements by attributes or text, so it is more robust.

11. What is the difference between findElement and findElements?

findElement returns the first matching element or throws NoSuchElementException. findElements returns a list, which is empty if nothing matches.

12. What is the difference between close() and quit()?

close() closes the current window; quit() closes all windows and ends the WebDriver session.

13. How do you handle dropdowns?

For <select> elements, use the Select class with selectByVisibleText, selectByValue or selectByIndex. Custom dropdowns are clicked like normal elements.

14. How do you handle alerts, frames and windows?

Use switchTo().alert() to accept or dismiss alerts, switchTo().frame() for iframes (and defaultContent() to return), and switchTo().window(handle) using window handles for tabs and windows.

Waits and synchronisation

15. What types of waits are there?

Implicit wait (a global timeout for finding elements), explicit wait (WebDriverWait with a condition) and fluent wait (explicit wait with custom polling and ignored exceptions).

16. Why avoid Thread.sleep() or time.sleep()?

Fixed sleeps either wait too long (slow tests) or not long enough (flaky tests). Explicit waits continue as soon as the condition is met.

17. Should you mix implicit and explicit waits?

No. Mixing them can cause unpredictable wait times. Prefer explicit waits.

18. What causes StaleElementReferenceException?

The element was found, but the page re-rendered or the DOM changed, so the reference is no longer valid. Find the element again, ideally inside a wait.

Frameworks and design

19. What is the Page Object Model?

A design pattern where each page or component is represented by a class containing its locators and actions, so tests stay readable and locators are maintained in one place. See the Page Object Model guide.

20. What is a data-driven framework?

Tests read input and expected data from external sources (CSV, Excel, JSON) or test parameters, running the same flow with many data sets.

21. What is a hybrid framework?

A combination of approaches, typically Page Object Model, data-driven tests and reusable utilities, plus reporting and configuration.

22. Explain the framework you built.

Describe the language and test runner, folder structure (pages, tests, utilities, test data, config), how you handle waits and configuration, reporting, how tests run in CI and one problem you solved. Read how to build a test automation framework.

23. What are TestNG annotations?

Annotations such as @Test, @BeforeMethod, @AfterMethod, @BeforeClass and @DataProvider control test execution, setup, teardown and data.

24. How do you run tests in parallel?

Through the test runner (TestNG parallel settings, pytest-xdist) and Selenium Grid or a cloud grid, keeping tests independent with their own data and driver instances.

25. How do you take a screenshot on failure?

Use a listener or hook (for example a TestNG listener or a pytest hook) that calls the screenshot method when a test fails and attaches the file to the report.

Flakiness and maintenance

26. What is a flaky test?

A test that sometimes passes and sometimes fails without code changes.

27. How do you reduce flaky tests?

Use stable locators and explicit waits, make tests independent, control test data, avoid relying on test order, and investigate root causes before adding retries.

28. How do you handle dynamic elements?

Use locators based on stable attributes or text, partial matching (contains()), and waits for the expected state.

API testing and CI

29. Why test APIs as well as the UI?

API tests are faster and more stable, and they find problems in business logic before the UI is involved. See the API testing tutorial.

30. Which status codes should you know?

200 OK, 201 Created, 204 No Content, 400 Bad Request, 401 Unauthorized, 403 Forbidden, 404 Not Found, 409 Conflict and 500 Internal Server Error.

31. What is REST Assured?

A Java library for writing readable API tests in a given/when/then style.

32. How do you run automation in CI/CD?

Configure a pipeline (GitHub Actions, Jenkins or GitLab CI) to install dependencies, run tests in headless browsers on every push or pull request, and publish reports and screenshots.

33. What is headless testing?

Running a browser without a visible window, used on servers and CI where there is no display.

Scenario questions

34. A test passes locally but fails in CI. What do you check?

Timing and waits, screen size and headless differences, test data and environment configuration, browser versions, and parallel tests sharing data. Check screenshots, logs and traces from the CI run.

35. How would you automate login for many test cases?

Create a reusable login step or page object, or log in through an API and reuse the session or cookies so that UI tests focus on the feature under test.

How to prepare

  • Build a small framework and be ready to explain every folder and design choice.
  • Practise core Java or Python; see Java interview questions and Python interview questions.
  • Revise testing fundamentals and test case design.

Practise with mentors in the Automation Testing course or the AI mock interview.

===FAQ=== Q: What Selenium topics are asked most in interviews? A: Locators, waits, handling alerts, frames and windows, common exceptions, the Page Object Model, TestNG or pytest, framework design, parallel execution and CI. Q: How should a fresher prepare for an automation testing interview? A: Learn testing fundamentals, one programming language, Selenium basics and a framework, build a small project, and practise explaining it clearly. Q: Are coding questions asked in automation testing interviews? A: Yes. Expect basic programming questions such as string and array problems in Java or Python, plus writing small Selenium or API test snippets. Q: Should I learn Playwright for interviews? A: Selenium remains common in interviews, but Playwright knowledge is increasingly valued. Knowing the concepts of both is an advantage.
