# Interview Studio implementation plan

1. Audit and additive foundation: app, identities, routes, migrations, scoped UI, staff management.
2. Versioned original catalog, configuration validation, owner-scoped sessions, chat, server timer and recovery.
3. Monaco editor, revisioned draft persistence, isolated database execution queue and dedicated runner.
4. Structured six-dimensional AI reports, immutable automated evidence, history and actual-data analytics.
5. Optional browser speech adapters with consent and typed fallback; no retained audio.
6. Original DSA catalog, filters, roadmaps, company-style preparation and persistent progress.
7. Persisted system/low-level design documents, diagrams and contextual review.
8. Tutor with approved-source retrieval and notebook; no unsupported course-content claims.
9. Existing staff admin extension, content and weight management, usage overview.
10. Regression tests, builds, SEO validation, production configuration and explicit acceptance gap log.

Each phase must produce working behavior and documented limitations. UI availability is not production acceptance. AI calls require server credentials/model configuration. Sandboxed execution requires a running, dedicated Docker host and trusted runtime images. Production deployment is not authorized by merely modifying this existing repository; preserve its established release path.

Sprint outcomes, tests, file changes, API/schema changes and remaining acceptance gaps are tracked in INTERVIEW_STUDIO_DELIVERY.md as work proceeds.
